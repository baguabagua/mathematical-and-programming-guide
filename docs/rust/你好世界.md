## A+B Problem

```rust
use std::io;

fn main() {
    let mut input = String::new();
    io::stdin().read_line(&mut input).expect("读取失败"); // 读取输入的一行到字符串 input
    
    let numbers: Vec<i32> = input
        .split_whitespace() // 从空白字符处分裂成多段
        .map(|s| s.parse().expect("解析失败")) // 每段尝试转换为整数
        .collect(); // 收集到容器

    assert_eq!(numbers.len(), 2); // 断言解析出的数字数量为 2

    let (a, b) = (numbers[0], numbers[1]);
    
    println!("{}", a + b);
}
```

## 注释

与 C++ 类似，支持 `/* */` 和 `//` 两种风格的注释。

## 基本类型

有符号整数：`i8, i16, i32, i64, i128, isize`

无符号整数：`u8, u16, u32, u64, u128, usize`

浮点数：`f32, f64`

特殊：`bool, char`

学过 C/C++ 的应该对这些基本类型大都比较熟悉。`i32` 就相当于 `int`，`i64` 相当于 `long long`，`u32` 相当于 `unsigned`，`f32, f64` 相当于 `float, double`。

`isize` 和 `usize` 是比较特殊的类型，具体的位数与系统有关，目前主流是 64 位系统，所以它们都是 64 位的。**数组下标只能使用`usize`类型。**

`char` 在 Rust 中与在 C/C++ 中不太一样，是 4 字节 Unicode 标量值。

## 定义变量

`let [变量名]: [类型] = 初始值;` 例如：`let a: i32 = 5;`

定义变量时不赋予其初值是可以的，但是在首次使用前必须赋初值，否则编译报错。实践上很少会这么写。

定义变量时，不显式声明类型可能是可以的。这取决于上下文有没有提供足够多的信息可以推导出变量的类型。例如上面的例子中，就可以直接写 `let a = numbers[0];`，因为上文已经确定了 `numbers[0]` 的类型是 `i32`。直接写 `let a = 5;` 也是可以的，此时 `a` 的类型会根据下文用到 `a` 的地方确定，例如如果 `a` 被用作数组下标，则会确定类型是 `usize`。如果通过上下文无法确定类型，则整数默认的类型是 `i32`，浮点数默认的类型是 `f64`。

Rust 中变量默认是**不可变**（immutable）的。也就是说，不能被赋值（除了赋初值）。如果你希望变量可变，在定义它的位置在它前面加上 `mut`。例如，`let mut a = 5;`

> 变量不可变，听起来很奇怪。实际上变量中的变和可变性中的变是两回事。变量中的变是和常量相对的，指的是可以在运行时确定值（常量必须在编译时就被确定值，另外变量只是说可以在运行时确定，没有要求编译时一定不能确定）。可变与不可变是指能不能被修改。
>
> 简单介绍一下常量：`const PI: f64 = 3.14;`。和变量的区别：必须显式声明类型，必须不可变，可以定义在函数之外，包括全局作用域。

与在 C/C++ 中不同，一般来说，Rust 中一个语句只能定义一个变量。但是上面的代码用了这样的写法：`let (a, b) = ...`。这是利用元组类型进行的取巧。元组会在后续章节再介绍。

Rust 中不能使用 let 在全局作用域定义变量。

Rust 允许在同一作用域中定义重名的变量，称为变量遮蔽（Shadowing）。有点类似 C/C++ 中内层作用域定义与外层作用域重名的变量，把外层作用域的变量遮蔽。

> 变量遮蔽被部分人认为违反了一些应该遵循的设计原则，包括“明确优于隐式”“最小惊讶原则”。但它最终在 Rust 中被保留，这也是经过考量的。变量遮蔽在很多场景提供了很多便利性和安全性。可以让一个连续的处理流程中不需要起一堆乱七八糟的变量名，也可以转换变量名的类型或可变性。

Rust 中，定义的变量未被使用，或可变变量没有修改过，都会被编译器警告。如果这是你的预期行为，应该在未使用的变量名前加下划线，或直接以下划线命名。或者，使用 #[allow(unused_variables)] 或 #[allow(unused_mut)] 这样的标记。这种标记应该严格控制使用范围。

下划线开头的变量被使用或未被使用都可以，主要用于抑制未使用警告。例如 `let _x = 5;`。单独的下划线则是占位符，表示忽略一个值，例如 `let _ = 5;`，后续 `_` 仍然是不能使用的。

## 标识符命名规范

相比 C/C++，Rust 对标识符有更严格的命名规范。具体来说：

1. 变量名和函数名应当是纯小写字母的下划线命名。如 `my_integer`。
2. 常量名应当是纯大写字母的下划线命名。如 `MAGIC_NUMBER`。
3. 类型名（Enum、Struct、Trait 的名称）应当是大写字母开头的驼峰命名。如 `MyStruct`。

不遵循这些命名规范不会导致编译失败，但会触发编译器警告。

> 不同语言对待警告的态度不一样。在 Rust 中，警告一般都是要避免的。

## 运算符

C/C++ 中大部分运算符都在 Rust 中仍然存在，包括：

1. 算术运算符。`+, -, *, /, %`。
2. 关系运算符。`<, >, ==, >=, <=, !=`。
3. 逻辑运算符。`&&, ||, !`。同样有逻辑短路。
4. 位运算符。`&, |, ^, !, <<, >>`。注意按位取反是 `!`。
5. 赋值和复合赋值。`=, +=, &=`等。
6. 引用和解引用。`&, *`。用法和 C/C++ 中区别比较大。

没有自增自减运算符 `++`, `--`、三目运算符 `?:`、逗号运算符 `,`。

> 逗号和自增自减把一些应该显式写明的东西挤在一起，把代码搞得晦涩，增大了代码的阅读难度，也增加了出错可能，不符合 Rust 语言哲学。
>
> 三目运算符在 Rust 中可以被 if-else 替代。见后续章节。

存在的运算与 C/C++ 的主要区别：

1. 有更严格的类型限制。主要是 Rust 没有隐式类型转换。而且这些运算符用在基本类型上时，都要求参与运算的值类型相同。
2. 赋值运算无返回值，或者说返回值是 `()` (Unit，可以称为单元)。这拒绝了像 `a=(b=5);` 这样的连续赋值。

Rust 可以用 `as` 进行显式类型转换，但是只支持数值类型（整数、浮点数）之间的转换。特别地，`u8` 可以转换为 `char`（根据 ASCII 码）。示例：

```rust
let a: i32 = 6;
let b: f64 = 3.5;
let c: u8 = 65;

println!("{} {}", a as f64 + b, c as char); // 输出：9.5 A
```

## 字面量

整数字面量：`5, 638`。类型会根据上下文自动推导，无法确定默认 `i32`，也可以通过后缀显式指定，如 `42i64, 42u32, 42usize`。

支持多种进制以及下划线分隔，例如 `1_000_000, 0xffu16, 0xFF, 0o777_555, 0b1111_0000i8`。

浮点数字面量：`5.0, 3.14`。类型会根据上下文自动推导，无法确定默认 `f64`，也可以通过后缀显式指定，如 `3.14f32, 5.0f64`。

支持科学记数法，如 `1e9, 2.5e-2, 3e6f32, 1E9`。

支持下划线分隔。支持十六进制，但必须包含二进制指数，用 `p` 或 `P` 分隔。如 `0x1.8p3` 表示 $(1 + \frac{8}{16}) × 2^3 = 1.5 × 8 = 12.0$。

布尔字面量：`true, false`。类型为 `bool`。

字符字面量：`'a', '🐱'`。字符字面量用单引号包裹，类型为 `char`，是 4 字节 Unicode 标量值。

字符串字面量：`"hello"`。字符串字面量用双引号包裹，类型为 `&'static str`。这个类型涉及 Rust 比较深入的知识，包括引用、切片、生命周期。初学者可以先把它当成一个特殊的整体。

原始字符串字面量：`r#"hello"#`。类型为 `&'static str`。

## 字符串

在 Rust 中，字符串是比较复杂的。初学者可以先记住两个类型：`&'static str` 和 `String`。前者是字符串字面量的类型，编译时确定，不可变，只是个引用。后者是通常用到的字符串，可变，拥有完整所有权。

上面的例子已经展示了 `String` 的一些用法，当然可能现在还不能完全看懂。这里再给出一些示例：

```rust
let s1 = String::new(); // 空字符串
let s2 = String::from("hello"); // 从字面量创建
let mut s3 = String::from("hello");
s3.push_str(", world"); // 追加
println!("{}", s3); // hello, world
// 字符串切片 &str
let slice: &str = &s3[0..5];
println!("{}", slice); // hello
```

## format 和 println 宏

Rust 中以 `!` 结尾的，看起来像函数的东西叫做**过程宏**。上面示例中的 `println!, assert_eq!` 都是过程宏。

这里先介绍 format 宏。它的作用是生成格式化的字符串（`String` 类型）。有点类似 C 中的 `sprintf`。例如：

```rust
let a = format!("{}+{}={}", 3, 5, 3+5); // 相当于 let a = String::from("3+5=8");
```

它的第一个参数是用双引号包裹的，其中可以有若干个用花括号包裹的占位符 `{}`。这些占位符会与后面的参数一一对应。这些参数可以是基本类型或字符串类型，也可以是任何实现了 `std::fmt::Display` Trait 的自定义类型。

实际上有更多不同的占位符，可以产生更多样的格式化效果。例如 `{:?}` 用于调试，`{:b}, {:o}, {:x}` 用于控制输出数字的进制，`{:.2}`控制精度（保留两位小数），等等。

print 和 println 宏的用法和 format 宏类似，但是不产生值，而是将对应的字符串直接输出。区别在于 println 会自动在末尾添加一个换行符。

## assert 宏

断言。如果断言不成立，则程序直接崩溃。这在调试中很有用。另外，也会有助于一些编译优化。

`assert!(boolean);` 直接断言。这里要求 `boolean` 是一个 `bool` 类型的值。

`assert_eq!(a, b);` 断言 `a` 和 `b` 相等。等价于 `assert!(a == b)`。

`assert_ne!(a, b);` 断言 `a` 和 `b` 不相等。

另外还有一些会让程序直接崩溃的宏：

`panic!();` 可以无参数或带一个字符串参数。效果就是让程序直接崩溃。带的字符串参数会在崩溃时输出出来。

`todo!();`, `unreachable!()`, `unimplemented!()` 都差不多，也是让程序直接崩溃。语义上有所区别，分别用于表示要写但还未写的代码，逻辑上无法到达的位置，还未实现的部分。

另外，示例代码中有多处 `.expect("...")`，这个是用于在一个过程失败时让程序立刻崩溃。不过 expect 并不是宏，而是 `Result` 类型的方法。这个会在后续章节讲解。

## 定义函数

`fn [函数名]([参数列表]) -> [返回值类型] { 函数体 }`。无返回值时可以不写 `-> [返回值类型]` 这部分。上面两个例子中都定义了主函数 `fn main() { ... }`，参数列表为空，无返回值。和其它语言一样，Rust 中，主函数是程序的入口。

## 导入

上面的例子中出现了 `use std::io;` 这是导入了 `std` 库的 `io` 模块，下面就直接写 `io::stdin()` 来使用了。如果没有导入，则使用时必须写出完整的路径 `std::io::stdin()`。也可以导入函数，例如 `use std::io::stdin`，使用时可以直接写 `stdin()`。

用通配符 `*` 可以导入一个模块中的所有东西，例如 `use std::io::*;`。不过要谨慎使用。一般只推荐对自己写的模块，或一些库的 `prelude` 模块这样做。

导入时可以用 `as` 进行重命名，例如 `use std::io::stdin as input;`

可以用大括号同时导入多项，例如

```rust
use std::io::{self, Write, stdin};
use std::collections::{HashMap as Map, BTreeMap as BMap};
```
